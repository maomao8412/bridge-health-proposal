02 / 核心算法

BPE是怎么工作的？

字节对编码——一步步看Token是怎么"合并"出来的

BPE算法原理

BPE（Byte Pair Encoding，字节对编码）的思路非常简单：

1️⃣ 初始时，每个字（或字节）都是一个独立的token
2️⃣ 找到语料中相邻出现频率最高的一对token
3️⃣ 把它们合并成一个新的token
4️⃣ 重复第2-3步，直到词表达到目标大小

就这么简单——每次合并"最常在一起出现的那一对"，就能用最少的词表容量，压出最短的序列。

03 / 核心矛盾

词表大小 vs 序列长度

一个变大，另一个就变小——这是一个零和博弈吗？

为什么这是一个"权衡"问题？

你不能同时拥有"最小的词表"和"最短的序列"——两者方向相反：

词表越小 → 每个token承载的信息越少 → 需要更多token才能表达同样内容 → 序列越长

词表越大 → 每个token承载的信息越多 → 需要更少token → 序列越短

⚖️
这是一个最优化问题
词表大小决定了模型的参数量（影响训练成本），序列长度决定了推理速度和成本。 Token分词的目标就是：在总词表预算内，让序列长度尽可能短——从而让总计算成本最低。

05 / 最优解

总成本曲线与最优点

为什么大家都选5万左右的词表？背后有一条U型曲线

📈 可视化：U型成本曲线

训练成本随词表增大而上升（参数量变大），推理成本随词表增大而下降（序列变短）。两者相加，总成本是一条U型曲线——最低点就是最优解。

🎯
最优解在哪里？
对于大语言模型来说，词表一般在3万-10万之间。 GPT-3的词表是5万左右，Llama系列也是3万-12万不等—— 不是巧合，是大家都在这条U型曲线的最低点附近找到了最优解。

而中文模型因为单字信息密度高，最优词表通常比英文小一些—— 因为同样数量的token，中文能表达更多信息。
06 / 本质

为什么说这是经济学问题？

Token不只是一个技术概念，它从出生就带着经济属性

三个经济学视角

1️⃣ 资源稀缺性

算力是稀缺的，内存是有限的。在有限的计算资源下，怎么安排词表和序列，让效率最高？ 这就是经济学最核心的问题——稀缺资源的最优配置。

2️⃣ 成本-收益分析

扩大词表的成本是参数量增加（训练更贵）， 收益是序列变短（推理更快更便宜）。 经济学就是研究"多花一块钱成本，能不能换来多于一块钱的收益"—— Token设计完全符合这个分析框架。

3️⃣ 边际递减规律

词表从1000扩大到5000，效果提升很明显；但从10万扩大到20万，提升就很小了。 这就是经济学中的边际收益递减——每多投入一单位资源，带来的增量收益越来越小。

💎
一句话总结
Token不是"为什么不用字"的技术问题， 而是"在算力有限的前提下，怎么设计最经济的文本表示方式"的最优化问题。 它的目标函数是：在可接受的词表大小约束下，最小化处理单位文本的计算成本。
