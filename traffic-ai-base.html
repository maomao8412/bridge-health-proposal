💡 中试基地的"中试"是什么意思

"中试"=中间试验。就是把实验室里的大模型技术，放到真实交通场景中验证可行性、效果和成本， 为规模化推广做准备。所以中试基地既要能训模型，也要能做应用验证，还要建立评测标准。

L2 · DATA

数据层 · 交通行业数据工厂

数据是垂直大模型的灵魂。交通行业数据量大、种类多、格式杂，需要一套完整的流水线处理。

📊

多源数据接入

接入各类交通数据源：路网监测、收费数据、视频监控、巡检记录、气象数据、交通事故、施工信息…

结构化 + 非结构化 实时 + 离线
🧹

数据清洗与去重

原始数据质量参差不齐，需要去重、去噪、过滤低质数据。常用 MinHash、SimHash 等算法做大规模去重。

MinHash / SimHash 质量打分
🏷️

数据标注平台

监督微调（SFT）需要标注数据。标注平台支持文本标注、图像标注、视频标注、RLHF人类偏好标注等。

SFT标注 偏好标注
🔒

数据安全与脱敏

交通数据涉及车牌、人脸、位置等敏感信息，必须做脱敏处理。还要通过合规审查、版权检查。

PII脱敏 合规审查
📚

行业知识库构建

把交通领域的规范、标准、论文、手册、案例等结构化，形成行业知识库，用于RAG和预训练。

知识图谱 文档解析
📐

数据质量治理

建立数据质量评估体系：准确率、覆盖率、时效性、一致性、多样性。定期审计，持续优化。

质量指标 持续迭代
⚠️ 为什么数据层是最花钱的

十个亿的项目里，数据相关的投入通常占30%~40%。因为买GPU是一次性的， 但数据采集、标注、治理是长期持续的。垂直大模型的效果上限，本质是由数据质量决定的。

L3 · MODEL

模型层 · 交通垂直大模型训练

在通用大模型基础上，用交通行业数据做"深加工"，让模型懂交通、会交通、能干活。

📖

继续预训练（PT）

用大量交通行业文本（规范、论文、报告、新闻等）继续训练基础模型，让模型"学到"交通领域的知识和语言风格。

百亿token级 全参数 / LoRA
🎯

监督微调（SFT）

用高质量问答/指令数据教模型"怎么回答问题"。从闲聊模式切换到任务模式，这是垂直化最关键的一步。

几千~几万条 质量 > 数量
⚖️

人类偏好对齐（RLHF/DPO）

让模型的回答更符合人类偏好——更专业、更安全、更有用。DPO是现在更流行的简化版，训练成本低。

RLHF / DPO 偏好数据
🌐

多模态训练

交通场景有大量视频和图像数据（监控、巡检照片、遥感图等），需要图文对齐训练，让模型能"看懂"。

图文对齐 视频理解
🧬

模型选型与基座

选择什么基座模型？多大参数？开源 vs 自研？交通行业建议7B~70B之间，根据场景选不同大小。

Qwen / Llama 7B ~ 70B
🔧

训练工程

分布式训练框架（DeepSpeed/Megatron）、混合精度训练、梯度检查点、ZeRO优化…让大模型在多卡上高效训练。

DeepSpeed FSDP
💡 你已经练过的 LoRA 就是 SFT 的轻量化版

你今天练的 LoRA 微调，本质就是 SFT（监督微调），只不过只训了一小部分参数。 真正的中试基地里的 SFT 是全参数微调，数据量也大得多（几万~几十万条），但原理是一样的。 你今天学的东西就是垂直大模型训练的最小单元。

L4 · CAPABILITY

能力层 · 让模型具备实用能力

光有一个"懂交通的模型"还不够，还需要给它装上各种"技能模块"，才能真正解决业务问题。

🔍

RAG 检索增强生成

模型回答问题前，先从行业知识库中检索相关资料，再基于资料生成答案。解决"幻觉"问题，提高准确性。

向量检索 知识增强
🛠️

工具调用（Function Calling）

模型可以调用外部工具——查数据库、调API、跑计算、读文件。不再只是"说话"，而是能"做事"。

API调用 数据库查询
🧠

规划与推理

让模型能思考复杂问题——Chain of Thought、ReAct、Plan-and-Execute。先想再做，而不是张口就答。

CoT / ReAct 多步推理
🖼️

多模态理解

看懂交通监控视频、识别路面病害、解读交通标志、分析卫星遥感图…图文融合是交通AI的关键能力。

VLM / 多模态 视频理解
💬

长上下文处理

交通文档动辄几十上百页（检测报告、设计图纸、应急预案），需要模型能"读完一整本书"再回答。

32K~128K 长文档理解
🔌

插件/技能生态

把交通行业的各种能力封装成插件——交通流量预测、路径规划、事故推演、信号控制优化…

插件市场 能力复用
L5 · AGENT

应用层 · 交通行业智能体

把模型能力包装成具体的"AI员工"，每个智能体负责一个具体的交通业务场景。

🛣️

桥梁/道路巡检智能体

自动分析巡检记录和图像，识别病害，生成检测报告，给出维修建议。替代80%的人工案头工作。

病害识别 报告生成
🚦

交通调度智能体

实时分析交通流量，给出信号控制优化建议、分流方案、事件处置策略。辅助交通指挥决策。

流量分析 调度决策
🚨

应急处置智能体

事故/灾害发生时，快速生成处置预案，调度救援资源，协调多部门联动。辅助应急指挥。

预案生成 资源调度
👷

运维管理智能体

基于全路网设施状态数据，智能安排养护计划、分配养护资源、优化预算使用。

养护决策 资源优化
💼

客服/咨询智能体

面向公众的出行咨询、收费答疑、投诉处理、政策解读。7×24小时服务，降低人工客服压力。

智能客服 公众服务
🔬

科研辅助智能体

交通行业的科研助手——文献综述、数据挖掘、实验设计、论文写作辅助。提升科研效率。

科研加速 创新孵化
L1 · INFRASTRUCTURE

算力层 · 训练与推理基础设施

大模型是"算力吞金兽"。算力层要解决的问题是：怎么把一堆GPU高效地用起来，又快又省钱。

🖥️

GPU 集群

几千张GPU卡组成的训练集群。主流是NVIDIA A100/H100/H800，国产昇腾910也在替代。

千卡级集群 A100 / H800
⚡

分布式训练框架

把一个大模型拆到几百张卡上训练。数据并行、张量并行、流水线并行……DeepSpeed 和 Megatron 是标配。

DeepSpeed Megatron-LM
🚀

推理加速

模型上线后怎么跑得快、成本低。量化（INT4/INT8）、vLLM、TensorRT-LLM、PagedAttention…

vLLM / TensorRT 量化压缩
📦

资源调度与运维

多用户共享集群，怎么分配算力？K8s + GPU调度 + 排队系统。还要监控、告警、故障恢复。

K8s GPU调度
💰 算力有多烧钱

一张 H800 约 20~30 万，一个千卡集群就是几十亿。电费一年几千万。 所以中试基地的算力规划非常关键——不是买越多越好，而是匹配业务需求、逐步扩容。

L6 · EVALUATION

评测层 · 交通大模型Benchmark

怎么证明你的"交通大模型"比通用大模型好？需要一套行业评测标准。这是中试基地非常重要的产出。

📝

行业知识评测

建立交通行业的标准化题库——道路工程、桥梁工程、交通规划、交通法规、智能交通…选择题+问答题。

标准化题库 分级难度
🏭

场景任务评测

在真实业务场景中评测——巡检报告准确率、调度方案合理性、应急处置有效性。不是跑分，是看效果。

业务指标 场景化评估
🛡️

安全与对齐评测

模型有没有偏见？会不会给错误建议？能不能保守处理不确定的问题？安全是行业大模型的底线。

红队测试 安全对齐
📊

性能与成本评测

推理速度多少？并发多少？单token成本多少？不同硬件上的表现？工程落地必须算经济账。

延迟/吞吐 ROI分析

实战学习路线 · 从你现在的水平出发

不要一上来就啃分布式训练。从你已经掌握的 LoRA 微调出法，一步步往上走，每一步都有实战产出。

阶段一 · 入门巩固（1~2周）

小模型微调全流程熟练

把今天学的东西练熟，能独立完成从数据准备到微调部署的完整流程。

数据清洗与格式化 LoRA/SFT 微调 效果评估对比 模型推理部署 FastAPI 服务
阶段二 · 能力拓展（2~4周）

RAG + 工具调用 + 简单智能体

给模型加上"外挂"——能查资料、能调用工具、能做简单的多步推理。做一个交通问答Agent原型。

向量数据库 RAG检索增强 Function Calling ReAct 推理 Agent框架（LangChain等）
阶段三 · 进阶训练（1~2月）

中规模模型全参数微调

从LoRA升级到全参数SFT，理解分布式训练的基本原理。能操作1~2张GPU训一个7B模型。

全参数微调 DeepSpeed ZeRO LoRA vs 全参对比 DPO 偏好对齐 训练数据配比策略
阶段四 · 中试基地级（长期）

大规模训练 + 多模态 + 评测体系

理解千卡集群训练流程、多模态模型训练、行业Benchmark构建。达到能把控中试基地技术路线的水平。

继续预训练(PT) 多模态训练 MoE 模型 评测体系设计 算力规划与成本控制
